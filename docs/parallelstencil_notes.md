# ParallelStencil.jlの学習記録

## 1. 学習目的

ParallelStencil.jlの基本的な使い方を学び，数式に近い形で差分計算を記述する方法を理解する．また，逐次計算と並列計算の結果および計算時間を比較する．

## 2. 基本的な使い方

### 2.1 初期設定

```julia
using ParallelStencil
using ParallelStencil.FiniteDifferences2D

@init_parallel_stencil(Threads, Float64, 2)
```

- Threads：CPUでのスレッド並列計算を利用する．
- Float64：倍精度浮動小数点数を使用する．
- 2：二次元の計算を行う．

### 2.2 配列の作成

```julia
T = @zeros(Nx, Ny)
```

温度を格納する二次元配列を作成する．

## 3. 差分計算

温度分布を T(x, y) = x² + y² として，一階微分，二階微分およびラプラシアンを計算した．

### 3.1 一階微分

```julia
@all(dTdx) = @d_xa(T) / dx
@all(dTdy) = @d_ya(T) / dy
```

隣り合うセル中心の温度の差を格子幅で割ることで，セル境界面における温度勾配を求める．

### 3.2 二階微分

一階微分の結果に対して，再度差分計算を行う．

一階微分と二階微分で同じ関数を使用できることを確認した．ただし，配列の大きさが変化するため，計算範囲に注意する必要がある．

### 3.3 ラプラシアン

x方向とy方向の二階微分を，同じ位置で足し合わせることで求めた．

理論値は4であり，計算結果と一致した．

### 3.4 配列の大きさ

| 物理量 | 配列の大きさ |
|---|---|
| 温度 | Nx × Ny |
| x方向一階微分 | (Nx − 1) × Ny |
| y方向一階微分 | Nx × (Ny − 1) |
| x方向二階微分 | (Nx − 2) × Ny |
| y方向二階微分 | Nx × (Ny − 2) |
| ラプラシアン | (Nx − 2) × (Ny − 2) |

今回は境界面や境界付近の一部を除いた内部の差分計算を行った．

## 4. 逐次計算と並列計算の比較

### 4.1 逐次計算

```julia
for j in 1:Ny
    for i in 1:(Nx-1)
        dTdx[i, j] = (T[i+1, j] - T[i, j]) / dx
    end
end
```

### 4.2 ParallelStencilによる計算

```julia
@parallel function derivative_x_parallel!(dTdx, T, dx)
    @all(dTdx) = @d_xa(T) / dx
    return
end
```

ParallelStencilを使用することで，for文や配列の添字を直接記述する必要がなくなり，数式との対応が分かりやすくなった．

### 4.3 計算結果の確認

- Maximum error：0.0
- Results match：true

今回の計算条件では，逐次計算とParallelStencilによる計算の結果が一致した．

## 5. 計算性能の比較

### 5.1 測定条件

- 計算領域：1000 × 1000
- 計算内容：x方向の一階微分
- 使用データ型：Float64
- 論理CPU数：16
- 測定回数：各100回
- 評価方法：計算時間の中央値

### 5.2 測定結果

| スレッド数 | 逐次計算 [ms] | 並列計算 [ms] | 高速化率 |
|---:|---:|---:|---:|
| 1 | 0.9100 | 1.1563 | 0.787 |
| 2 | 0.8696 | 0.7910 | 1.099 |
| 4 | 0.8642 | 0.6312 | 1.369 |
| 8 | 0.9306 | 0.6476 | 1.437 |
| 16 | 0.9547 | 0.7296 | 1.309 |

### 5.3 考察

1スレッドでは，並列処理のためのオーバーヘッドなどにより，逐次計算よりも計算時間が長くなったと考えられる．

複数のスレッドを使用することで計算時間が短くなり，4スレッドで最短の計算時間，8スレッドで最大の高速化率が得られた．

一方，16スレッドでは計算時間が増加した．スレッドの管理やメモリへのアクセスなどが影響した可能性がある．

このことから，スレッド数を増やすことで必ず計算が速くなるわけではないことが分かった．

## 6. 学習を通して分かったこと

- 差分演算をマクロによって簡潔に記述できる．
- 微分によって物理量の定義位置や配列の大きさが変化する．
- 同じ微分関数を繰り返し使用できる．
- 計算結果の一致と計算性能の両方を確認することが重要である．
- 計算内容や実行環境によって適したスレッド数が異なる．

## 7. 今後の方針

Oceananigans.jlおよびParallelStencil.jlで学んだ内容を参考に，既存課題の差分計算を数式に近い形で記述できるようにする．

さらに，微分などの演算処理を自分で実装し，計算結果の正しさ，可読性および計算性能を評価する．
